## 2. Identified Gaps & Formal Problem Statement

### 2.1 Core Gaps in Current Solutions

1. **The "Data Rich, Insight Poor" Smart Meter Paradox**: Smart meters produce 48 half-hourly readings daily, but consumers receive only retroactive monthly utility bills without granular diagnostic insights or appliance-level breakdown.
2. **Weather-Blind Consumption**: Household heating/cooling accounts for over 50% of domestic power variation. Without automated weather API integration, consumers cannot anticipate upcoming cold snaps or heat waves to pre-adjust thermostats and avoid peak tariff spikes.
3. **Time-of-Use (ToU) Tariff Misalignment**: Over 20% of modern households are on dynamic ToU tariffs. Consumers lack real-time decision-support tools to schedule high-drain appliances (EV chargers, heat pumps, washing machines) during off-peak hours.
4. **Generic vs. Context-Aware Recommendations**: Existing energy advice is static and generic. Advice fails to cross-reference the user's demographic context (ACORN group), historical baseline, and local microclimate.
5. **Static Dashboards vs. Interactive Conversational Problem Solving**: Traditional utility portals force users to interpret complex graphs. Users lack an interactive conversational copilot that can retrieve energy-saving heuristics (RAG), pull real-time weather forecasts via tool calling, and compute concrete financial savings on demand.

### 2.2 Formal Problem Statement

> **"Residential energy consumers and facility managers lack an intelligent, real-time mechanism to translate high-frequency smart meter telemetry and dynamic Time-of-Use (ToU) tariffs into actionable, cost-saving behaviors. Because existing systems fail to dynamically correlate household energy loads with microclimate weather forecasts and domain conservation knowledge, consumers suffer from avoidable peak-rate bill shocks, undetected standby anomalies, and inefficient appliance utilization.**
> 
> **To solve this, there is an urgent need for an Agentic AI Energy Copilot that couples Retrieval-Augmented Generation (RAG) over verified energy-efficiency literature with autonomous Weather & Tariff API Tool Calling, enabling users to receive instant energy diagnostics, predictive load-shifting schedules, and quantifiable financial savings through a natural conversational interface."**

### 3.1 Product Overview & Vision
* **Product Name**: **EcoPulse AI** (The Intelligent Energy & Tariff Optimization Copilot)
* **Mission**: Empower households and commercial property managers to cut energy consumption by 15–30% and reduce electricity bills through automated smart meter analytics, weather-predictive load scheduling, and conversational RAG-backed guidance.

   * *Pain Point*: Confused by fluctuating electricity bills; unaware of how small habits (standby power, dirty AC filters, water heater setpoint) translate to monthly expenses.
   * *Goal*: Ask plain-language questions to receive immediate diagnostics and personalized low-cost efficiency steps.

   * *Pain Point*: Subscribed to dynamic Time-of-Use pricing; vulnerable to massive cost spikes if high-power appliances run during peak grid windows.
   * *Goal*: Automatically check upcoming weather forecasts to predict cooling/heating loads and receive optimized run-time schedules.
3. **The Facility / Property Manager**:
   * *Pain Point*: Managing multiple units with irregular consumption spikes and undetected baseline leakage.
   * *Goal*: Benchmark energy profiles against demographic cohorts, run automated anomaly scans, and verify circuit-level load reduction.

#### FR-1: Conversational RAG Copilot & Knowledge Retrieval
* **Description**: A natural language conversational interface grounded on domain energy literature ([energy.txt](file:///c:/Users/Kaustubh/OneDrive/Desktop/LLM%20HACKATHON/energy.txt), [JETIR1405001.pdf](file:///c:/Users/Kaustubh/OneDrive/Desktop/LLM%20HACKATHON/JETIR1405001.pdf), and appliance specifications).
* **Capabilities**:
  * Answering queries on appliance optimization (HVAC thermostat setpoints, water heaters, lighting retrofit ROI, refrigeration maintenance).
  * Synthesizing mathematical formulas into explicit financial projections (e.g., *"Lowering water heater from 60°C to 50°C saves 18% on water heating costs, saving ~£38/year"*).
  * Citing verified source documents to eliminate LLM hallucinations.

#### FR-2: Autonomous Real-Time Weather API Tool Calling
* **Description**: Agentic tool calling mechanism interfacing with weather endpoints (`/forecast`, `/history`).
* **Capabilities**:
  * Fetching real-time ambient temperature, apparent "feels-like" temperature, solar cloud cover, and humidity for the household’s coordinates.
  * Detecting weather extremes (e.g., temperatures dropping below 5°C or exceeding 28°C) and triggering proactive load alerts.
  * Correlating historical weather records with smart meter spikes to separate weather-driven demand from appliance malfunction.

#### FR-3: Smart Meter Telemetry Analytics & Load Disaggregation
* **Description**: Ingestion and analytical processing of 30-minute smart meter readings (`hh_0` to `hh_47`) and daily aggregates.
* **Capabilities**:
  * Visualizing diurnal load profiles (morning peak, mid-day lull, evening peak, overnight baseload).
  * Disaggregating baseline standby loads (vampire power) vs. active operational spikes.
  * Providing daily, weekly, and monthly statistical comparisons (mean, max, median, standard deviation).

#### FR-4: Time-of-Use (ToU) Tariff Optimizer
* **Description**: Algorithmic engine that evaluates household tariff structures (`stdorToU`) against dynamic time blocks.
* **Capabilities**:
  * Identifying off-peak, standard, and peak surge time windows.
  * Providing optimal scheduling recommendations for heavy loads (dishwashers, washing machines, EV chargers, electric water heating).
  * Calculating exact cost differentials between peak and off-peak execution.

#### FR-5: Anomaly Detection & Phantom Load Sentry
* **Description**: Statistical and heuristic anomaly detection over time-series smart meter streams.
* **Capabilities**:
  * Detecting anomalous overnight baseloads (e.g., continuous draw >0.5 kWh between 01:00 and 05:00 indicating refrigeration seal failures, HVAC short cycling, or unmanaged server equipment).
  * Generating instant alert cards with step-by-step diagnostic checklists (e.g., flashlight door seal test from `energy.txt`).

#### FR-6: ACORN Demographic Cohort Benchmarking
* **Description**: Contextual energy scoring comparing the user’s household against anonymized peers within the same ACORN classification (Affluent, Comfortable, Adversity, Acorn A–Q).
* **Capabilities**:
  * Informing users whether they consume above or below their demographic median.
  * Providing tailored recommendations based on housing type, income bracket, and lifestyle factors.

### 4.2 Data Pipeline & Data Modeling

The platform processes three core data streams:
1. **Time-Series Telemetry**:
   * Raw 30-minute block CSVs (`hh_0` to `hh_47`) converted to columnar Apache Parquet format partitioned by month and household ID (`LCLid`).
   * Summary daily metrics (`daily_dataset.csv`) ingested into DuckDB for sub-millisecond aggregation queries (`SUM`, `AVG`, `MAX`, `STDDEV`).
2. **Contextual Knowledge & Embeddings**:
   * Knowledge ingestion from [energy.txt](file:///c:/Users/Kaustubh/OneDrive/Desktop/LLM%20HACKATHON/energy.txt) (appliance efficiency rules) and [JETIR1405001.pdf](file:///c:/Users/Kaustubh/OneDrive/Desktop/LLM%20HACKATHON/JETIR1405001.pdf) (circuit architectures and conservation literature).
   * Chunking strategy: Recursive character splitting with `chunk_size = 500` tokens and `chunk_overlap = 80` tokens.
   * Embeddings generated using `text-embedding-3-small` / `all-MiniLM-L6-v2` and stored in ChromaDB/Qdrant.
3. **External Real-time Weather Telemetry**:
   * Ingestion of Dark Sky / OpenWeather JSON payloads normalized into a unified schema: `timestamp`, `temp_c`, `apparent_temp_c`, `humidity_pct`, `cloud_cover_pct`, `precip_rate`, `uv_index`.

#### Core Database Schemas

```sql
-- Household Metadata Table
CREATE TABLE households (
    lclid VARCHAR(20) PRIMARY KEY,
    tariff_type VARCHAR(10) NOT NULL, -- 'Std' or 'ToU'
    acorn_code VARCHAR(10),           -- 'ACORN-A' through 'ACORN-Q'
    acorn_group VARCHAR(20),          -- 'Affluent', 'Comfortable', 'Adversity'
    latitude DECIMAL(9, 6) DEFAULT 51.5074,
    longitude DECIMAL(9, 6) DEFAULT -0.1278,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Daily Energy Aggregation Table (DuckDB / Parquet View)
CREATE TABLE daily_meter_summary (
    lclid VARCHAR(20),
    reading_date DATE,
    energy_sum_kwh DECIMAL(8, 4),
    energy_mean_kwh DECIMAL(8, 4),
    energy_max_kwh DECIMAL(8, 4),
    energy_min_kwh DECIMAL(8, 4),
    energy_std_kwh DECIMAL(8, 4),
    baseline_night_kwh DECIMAL(8, 4), -- 00:00 - 05:30 aggregate
    PRIMARY KEY (lclid, reading_date)
);

-- Weather Telemetry Table
CREATE TABLE weather_hourly (
    recorded_at TIMESTAMP WITH TIME ZONE PRIMARY KEY,
    temperature DECIMAL(5, 2),
    apparent_temperature DECIMAL(5, 2),
    humidity DECIMAL(4, 2),
    cloud_cover DECIMAL(4, 2),
    wind_speed DECIMAL(5, 2),
    precipitation_type VARCHAR(20),
    weather_summary VARCHAR(100)
);
```

### 4.5 API Specifications (FastAPI Gateway)

#### 1. `POST /api/v1/chat/completions`
* **Purpose**: Primary conversational endpoint supporting streaming Server-Sent Events (SSE).
* **Request Payload**:
```json
{
  "household_id": "MAC000022",
  "messages": [
    { "role": "user", "content": "How will tomorrow's weather impact my electricity bill and what should I do?" }
  ],
  "stream": true
}
```
* **Response**: SSE stream containing token chunks, tool-call status tags, and metadata references.

#### 2. `GET /api/v1/analytics/household/{lclid}/diagnostic`
* **Purpose**: Computes instant energy diagnostic metrics for a given household over a date range.
* **Query Parameters**: `start_date`, `end_date`, `include_anomalies` (bool).
* **Response Payload**:
```json
{
  "household_id": "MAC000022",
  "tariff_type": "ToU",
  "acorn_group": "Affluent",
  "metrics": {
    "total_kwh": 342.15,
    "daily_mean_kwh": 11.40,
    "peak_window_ratio": 0.42,
    "standby_vampire_load_kwh": 0.35,
    "estimated_cost_gbp": 68.43
  },
  "anomalies_detected": [
    {
      "timestamp": "2013-01-14T03:30:00Z",
      "reading_kwh": 1.45,
      "expected_kwh": 0.22,
      "severity": "HIGH",
      "suspected_cause": "Refrigeration door seal leak or unmanaged heating appliance"
    }
  ]
}
```

#### 3. `GET /api/v1/weather/forecast`
* **Purpose**: Proxies and caches real-time weather forecasts with energy-specific thermal index indicators.
* **Response Payload**:
```json

```
